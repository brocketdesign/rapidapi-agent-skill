# Finding Profitable API Ideas

## Method 1 — Browse RapidAPI Trending

1. Go to https://rapidapi.com/hub
2. Sort by **Most Popular** in each category
3. Look for categories where:
   - Top APIs have 1000+ subscribers
   - But #5–#20 APIs have poor documentation
   - Or existing APIs are expensive ($50+/mo)
4. **Opportunity**: Build a better, cheaper, or simpler alternative

---

## Method 2 — Search "API" on Twitter/X and Reddit

Search: `"looking for API" OR "is there an API for" OR "need an API"`

Common pain points found this way:
- "Is there an API for X that's not $500/mo?"
- "The Y API is down again, alternatives?"
- "Need a simple API to do Z"

---

## Method 3 — Browse Public APIs and Add Value

Visit https://github.com/public-apis/public-apis

Find APIs that:
- Have confusing documentation
- Require complex auth setup
- Return messy, hard-to-use data
- Combine data you'd need 3+ APIs for

Then build a **cleaner, simpler wrapper** and sell access on RapidAPI.

---

## Method 4 — AI-Assisted Idea Generation

Prompt for your AI agent:
```
Generate 10 profitable API ideas for RapidAPI in the [CATEGORY] niche.
For each idea:
1. API name
2. What it does (1 sentence)
3. Who needs it (target user)
4. Potential monthly revenue (subscribers × $9.99)
5. Data source (free/paid)
6. Complexity to build (Low/Medium/High)

Focus on Low complexity ideas with high demand.
```

## Quick Validation (5 minutes)

Before building, do this:
1. Search RapidAPI: does it already exist? How many subscribers?
2. Google `"[topic] API"`: is there unmet demand?
3. Check Twitter: are developers complaining about existing solutions?

If the answer to any is "yes, there's demand and it's underserved" — build it.
